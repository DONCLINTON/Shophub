SHOPHUB UGANDA — FINAL DEPLOYMENT PACKAGE
========================================

This package is prepared for the existing production site:
https://shhop.netlify.app/

WHAT IS INCLUDED
----------------
- The existing marketplace frontend and Supabase integration.
- The full-screen product image viewer with tap-to-open, pinch/tap zoom,
  swipe navigation and previous/next controls. Its existing viewer code is
  preserved in this package.
- Buyer-request form/database alignment and rental posting support.
- The standalone property and rentals page at /brokerage/.
- A prominent “DEAL DIRECTLY WITH THE SELLER” notice replacing the misleading
  payment-provider badges. ShopHub does not collect or process payments.
- A sitemap containing the homepage, jobs, brokerage page and current product
  detail URLs already present in the checked-in sitemap.
- A GitHub Actions job that refreshes product/job/rental SEO URLs daily and
  creates crawlable static detail pages for active rentals.

IMPORTANT DATABASE STATUS
-------------------------
The buyer-request and rental database migrations have already been run by the
site owner. This package includes the SQL reference file but does not execute
SQL when deployed. Do NOT run another SQL migration just because this ZIP is
deployed. Only run SQL if a new, separately explained migration is supplied.

DEPLOY THROUGH THE EXISTING GITHUB REPOSITORY
---------------------------------------------
1. Download and extract this ZIP.
2. In the GitHub repository connected to the existing Netlify site, upload the
   CONTENTS of the extracted folder to the repository root. Do not upload the
   ZIP as one file and do not put the files inside an extra nested folder.
3. Replace matching files when GitHub asks. Keep the existing repository and
   unrelated files. Ensure index.html, brokerage.html, _redirects, sitemap.xml,
   robots.txt, service-worker.js, scripts/ and .github/ are at the root.
4. Commit the changes once. Netlify will run the configured Node 22 build
   step, fetch current public listings from Supabase, generate rental detail
   pages and refresh sitemap.xml before publishing.
5. Wait for this single deploy to finish before testing. Avoid repeatedly
   redeploying while a deploy is already running.

POST-DEPLOY CHECKLIST
--------------------
- Open the marketplace and confirm product cards and details load.
- Open a product, tap its photo, test full-screen view, zoom, pinch and swipe.
- Publish a buyer request and confirm it appears in the requests area.
- Open /brokerage/, confirm rentals display, and test rental contact links.
- Confirm a rental card has a “View property details” link. Individual static
  rental detail pages are generated by the daily SEO workflow.
- Confirm the footer says “DEAL DIRECTLY WITH THE SELLER” and does not display
  Visa, Mastercard, MTN MoMo, Airtel or “Secure Payments” claims.
- Open /sitemap.xml and /robots.txt.

GOOGLE INDEXING
---------------
- Submit https://shhop.netlify.app/sitemap.xml in Google Search Console.
- The sitemap includes the marketplace product URLs and /brokerage/.
- The Netlify build generates the current rental detail pages and sitemap
  during deployment. GitHub Actions also refreshes these files once per day
  (03:17 UTC) when listings have changed, or can be run manually from GitHub
  → Actions → Refresh ShopHub sitemap and rental SEO pages.
- Google decides whether and when to crawl or index a URL. A sitemap improves
  discovery; it cannot guarantee indexing or ranking.

PAYMENTS AND SAFETY
-------------------
ShopHub is a listing and contact platform, not a payment processor. Buyers and
sellers must contact one another, verify the item/property and agree on price,
payment method and delivery/collection directly. The website does not hold,
collect or guarantee payments.

SECURITY
--------
The frontend uses the Supabase public anon key. Never put a Supabase service-
role key or other secret in browser code or the GitHub repository. Public data
access must remain protected by the existing Supabase RLS and Storage policies.
